## Commands and effects

The new standalone world/save is version 6 with profile
`<origin>-slot-zero-v1` and session `<origin>-assignment-session-v1`.
It does not embed, migrate or expose v5 commands. Versions 1-5 retain their exact
meaning and bytes. Immutable fixture and full current twenty-entry mapping are
persisted; only mapping entry zero can change.

`import_assignment_reference` admits an exact fixture atomically.
`assignment_command` carries session ID, command ID, expected revision, club ID,
signed requested slot and staff ID. Only the two admitted IDs and literal slot 0
are supported; 256 must not alias through original low-byte coercion. Every new
accepted request performs one signed DWORD write at row byte offset 2, width 4,
including assignment of the already selected member; original return is 1 and
RNG draws zero. An identical transport retry returns its earlier event without
another transition. Command ID conflict, wrong session/revision/club, capacity,
member or slot errors reject without state mutation. These are host restrictions,
not recovered original diagnostic behavior.

`assignment_readback_command` has the same envelope and slot, without staff ID.
It returns tagged empty or stable staff identity and no mapping write, with zero
RNG. Explicit readback is recorded in host revision/history for deterministic
retry and save replay. Rendering/state queries perform no implicit original
operation; they may display the mapping and label the last explicit readback as
historical. Host event/history writes are separate from original game effects.

No other member/slot/row/cache state, null-player cleanup, clearing, swaps,
duplicate removal, appointment, object construction/freeing or live transition
is admitted. Other 19 mapping entries and all immutable projection fields remain
unchanged. The seven anomalous list entries are neither omitted from a claimed
complete squad nor relabelled as loans or sentinels.
