# Non-negotiables

Status: proposed programme contract, incorporating the user's explicit Rust and whole-game decisions. Gate exceptions require a recorded decision and visible scope change; passing tests must never silently redefine fidelity.

1. **Whole game.** A match runner, holiday simulator or menu mock-up is not completion. Every baseline feature belongs in the scope register, including UI, persistence, setup, management and competition-specific behaviour.
2. **Rust owns game behaviour.** Game rules, calendar, RNG, AI, financial calculations and state transitions live in Rust. React/TypeScript renders views and sends commands; it cannot maintain a competing version of rules. Python is research glue, not a second production engine.
3. **One exact baseline.** Initially target the unmodified official 3.9.68 executable and matching original data, starting in 2001. Record hashes from supplied files, executable image base, language, configuration and patches. Never invent hashes or blend modern-season rules into that baseline.
4. **Reference hierarchy.** The original executable is the behavioural reference. Bosman is an independently versioned execution/analysis platform requiring calibration. A match against Bosman alone cannot certify a match against the original.
5. **Faithful and extended are explicit profiles.** Faithful mode preserves observed original behaviour, including documented quirks when safe and reproducible. Each intentional deviation has an ID, reason, affected observations and tests. Extensions are opt-in, versioned and persisted in saves. A crash or invalid-state case is documented, not manufactured into a passing golden result.
6. **Reproducible evidence.** Every finding links to input hashes, build/tool versions, mode, seeds/full RNG state, command log, comparison policy and raw artifacts. Instrumentation changes are part of build identity. Missing evidence means unknown, not pass.
7. **Names are hypotheses.** Imported names/confidence stay separate from our behaviour verification. An address, plausible decompilation or LLM explanation does not prove semantics. Preserve contradictory evidence and review history.
8. **No weakened comparisons.** No auto-blessing golden results, broad field masks, arbitrary float tolerances or reseeding to hide divergence. Mask each proven nonsemantic field by exact path and reason; retain raw bytes. Failed/censored runs remain in denominators.
9. **Determinism is engineered.** Explicit numeric widths, overflow, signedness, rounding, iteration order, RNG consumption and simulated clock. Parallelism between experiments first; one deterministic mutation order within a world. Instrumentation must not consume game RNG or alter tested state unnoticed.
10. **Headless core.** Rust engine works without browser, renderer, filesystem or networking. Native and browser builds run the same command corpus. Host services enter through narrow adapters.
11. **Extensibility with compatibility.** Stable entity IDs, documented subsystem interfaces, versioned events and saves. New features cannot silently invalidate old saves or mutate a loaded compatibility profile. Never split legacy RNG into convenient new streams without a deliberate deviation.
12. **Bounded unattended work.** CPU/RAM/disk/time/token limits, leases, immutable attempts, cancellation, backpressure, watchdogs and recovery are required before continuous operation. A healthy process without simulation progress is not a healthy run.
13. **Evidence promotion is reviewed.** Automation may schedule approved experiments, deduplicate failures and draft mapping claims. It cannot promote hypotheses, rewrite baselines, merge implementation changes or install unreviewed generated code into persistent workers.
14. **Provenance travels with content.** Record licence/source/attribution for maps, code and fixtures. The repository's MIT licence does not relabel upstream GPL code. Original material stays in private inputs unless distribution rights are established.
15. **Progress means demonstrated coverage.** Publish separate inventory, execution, branch, semantics, implementation and integration measures with explicit denominators. No single 'engine mapped 95%' claim based on function naming or line coverage.
16. **A playable result remains the objective.** Introduce a thin Rust/browser vertical slice early. Each later subsystem ships with player workflows and save/reload behaviour, not just batch tests. Whole-game release requires completed seasons and human review of the CM01/02 experience.
