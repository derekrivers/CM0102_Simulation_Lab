## Inputs and read set

The [inventory helper](../../scripts/pc_r10_input_inventory.py) imports no project
capture parser. It reads only pinned retained image/heap or pinned R5 sparse
artifacts. Existing source/specimen/platform/capture provenance remains exactly
that of [R4](PC_R4_HUMAN_REGISTRY.md), [R5](PC_R5_CAPTURE.md) and
[R7](PC_R7_EFFECTIVE_PLAN.md). It launches no process except its own Python
research host, writes no input and executes no original game instruction.

Eight global DWORDs identify counts, tables, context, registry and date. Checks
cover bounded complete club (581-byte stride) and staff (110-byte stride) tables,
context through +0x605, full (club_count+32)*145-byte mapping allocation, both
complete 6,371-byte-stride ordinary banks, registry header and sixteen complete
0xa6ef-byte rows. The selected reserved staff row must have ID equal to its table
index and reciprocal club +0xcf / staff +0x39 links. The complete ordinary human
mapping row is hashed and all twenty signed DWORD entries at +2+4*i are counted.
The existing first-sixteen empty-branch qualification is not extended to a new
command by this inventory.

The helper also records, explicitly as a hypothesis, fifty DWORD pointer slots
at club +0xd7. Each in-table aligned pointer is checked for ID/index equality,
club reciprocity and nonnull staff +0x61. Invalid entries and link mismatches are
counted, never discarded into a claim of valid full membership. No player-linked
object is dereferenced. No names, native pointer values, raw IDs, bytes or private
paths appear in the public result. A nonnull link alone proves no pointee extent
or lifetime.

## Observed result and retained failures

The [receipt](evidence/pc-r10-input-inventory-v1.json) binds exact source, input,
private audit and retained failed-attempt hashes. Searches covered conventional
image.bin, heap.bin and capture.bin files under the two existing private evidence
roots; this is not a claim to have searched every disk or every possible format.
Ten artifacts were found: two retained image/heap pairs and six sparse copies.
All sparse copies have the existing R5 SHA-256. The second retained pair's heap
matches the pinned heap but its image differs; that pair is not newly admitted.
No extra independent nonempty input follows from duplicate artifact copies.

Both admitted states contain exactly one real reciprocal ordinary human binding.
All **twenty** standard mapping slots equal -1, the full mapping row hashes match,
and context +0x5f0 cache count is zero. Thus neither provides the requested
preexisting nonempty human lineup. The ordinary banks remain 17/28 slots; neither
an AI mapping nor an ordinary-bank slot is transplanted into a human binding.

The fifty-pointer candidate has 48 aligned staff pointers, zero ID/index
mismatches or duplicate IDs, two invalid nonzero values that are neither null nor
ffffffff, and five staff +0x39 club mismatches. All 48 aligned rows have nonnull
+0x61 links. A separate full-table scan finds 43 rows with the human club pointer
and nonnull +0x61. These are structural association observations, not admission
of a fifty-member squad. The unexplained two entries and five mismatches require
source/official-layout work by the projection lane before any membership claim.

Two initial inventory attempts stopped on overstrict candidate-membership
hypotheses: first reciprocal-club mismatch, then pointer outside the staff table.
Their exact sources and sanitized failure notes remain private. The revised
inventory reports those mismatches without relaxing any production or semantic
admission gate. Successful earlier receipts/source and final executed source are
also retained; no receipt was overwritten. Missing-input, wrong-image-identity and existing-output
controls pass, with a retained failure receipt and byte-identical existing output.
Python compilation passes. No native build, emulator or browser acceptance is
claimed for these research-only paths.
